## Крок 1. Процесна версія (20 хв)

На початок `protsesy.py`:

```python
import os
from concurrent.futures import ProcessPoolExecutor
```

Під функцією `poslidovno()`:

```python
def protsesamy(n):
    with ProcessPoolExecutor(max_workers=n) as ex:
        return list(ex.map(ryadok, range(H), chunksize=8))
```

Блок запуску внизу файлу замініть на:

```python
if __name__ == "__main__":
    t_base, chasy, base = zamir(poslidovno, 3)
    print("послідовно", [round(c, 2) for c in chasy], "мінімум", round(t_base, 2))

    for n in (1, 2, 4, 8, os.cpu_count()):
        t, chasy, r = zamir(protsesamy, 3, n)
        assert r == base, "результат розійшовся з послідовним"
        s = t_base / t
        print("процесів", n, [round(c, 2) for c in chasy], "мінімум", round(t, 2),
              "прискорення", round(s, 2), "ефективність", round(s / n * 100), "%")
```

⚠️ Дві умови, без яких процеси на Windows **не працюють**:

- увесь запуск — під `if __name__ == "__main__":`;
- `ryadok` — на **верхньому рівні** файлу, не всередині іншої функції.

Запуск займе 1–2 хвилини.

## Крок 3. Скільки коштує сам пул (10 хв)

У `protsesy.py`, під `protsesamy`:

```python
def porozhniy_pul(n):
    with ProcessPoolExecutor(max_workers=n) as ex:
        list(ex.map(abs, range(n)))      # кожен процес мусить реально стартувати
```

У блок запуску:

```python
    for n in (2, os.cpu_count()):
        t, chasy, _ = zamir(porozhniy_pul, 3, n)
        print("порожній пул,", n, "процесів:", round(t, 3), "с")
```

⚠️ `with ProcessPoolExecutor(n) as ex: pass` виміряє майже нуль:
пул запускає процеси лише тоді, коли з'являється перше завдання.

## Якщо щось пішло не так

| Що бачите | Що це означає | Що робити |
|---|---|---|
| процеси створюються без кінця, машина «стає» / `RuntimeError: ... bootstrapping phase` | запуск не під `if __name__ == "__main__":` | `Ctrl+C`; увесь запуск — під цією перевіркою |
| `AttributeError: Can't get attribute 'ryadok'` або `PicklingError` | функція всередині іншої функції чи лямбда | `ryadok` — на верхньому рівні файлу |
| `BrokenProcessPool` | процес-працівник упав | запустіть `poslidovno()` окремо — помилка в самій функції |
| у Jupyter / IDLE процеси не стартують або зависають | новий процес не може імпортувати функцію з інтерактивної сесії | запускайте файл із терміналу: `python 3-protsesy/protsesy.py` |
| 1 процес на кілька відсотків повільніший за послідовно | ціна пулу й пересилання | так і має бути — це джерело 2 у висновках |
| процеси повільніші за послідовно на будь-якому N | задача замала | розмір як на тижні 2 (один прогін 5–15 с) |
| ефективність понад 100 % на 2 процесах | кеш процесора або шум | мінімум із трьох; якщо стабільно — поясніть у висновках |
| `AssertionError` | порядок рядків змінився | `ex.map` зберігає порядок; не `as_completed` |
| порожній пул — 0,000 с | процеси не стартували | у пул треба дати завдання — див. крок 3 |

## ⭐ Хто закінчив раніше

По черзі, скільки встигнете. Результати — у кінець `vysnovky.md`.

**⭐1. `chunksize` (10 хв).** На `cpu_count()` процесів заміряйте `chunksize` = 1, 8, 50, 200.
Чому 200 гірше? Порахуйте: скільки шматків роботи на скільки процесів.

**⭐2. Процесів більше, ніж ядер (10 хв).** `2 × os.cpu_count()` процесів. Що з часом і ефективністю? Чому?

**⭐3. Практична межа (15 хв).** Заміряйте N = 2, 3, 4, 6, 8, … і знайдіть, де ефективність
падає нижче 80 %. Це і є відповідь на питання «чи варто купувати машину з більшою кількістю ядер»
для вашої задачі.

**⭐4. Справжня задача: без пересилання результатів (30+ хв).** Зараз кожен процес повертає
рядок-список, і його копіюють назад через `pickle`. Зробіть так, щоб процеси писали результат
у **спільний масив**:

- `arr = multiprocessing.Array("i", W * H, lock=False)` у головному процесі;
- передайте його через `ProcessPoolExecutor(max_workers=n, initializer=..., initargs=(arr,))`;
- функція рахує рядок і записує в `arr[y * W:(y + 1) * W]`, а повертає лише `y`.

Звірте результат з `base` через `assert`, заміряйте й поясніть: чому замок не потрібен
і наскільки виграли — або чому не виграли.
