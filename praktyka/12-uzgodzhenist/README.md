# Практична 12. Журнал замірів у трьох копіях: розходження, злиття, кворум

Тема 12 · до **8 балів** · практика — друга пара й початок третьої ·
з середини третьої пари — **кожен ділиться результатом**

Журнал замірів із тем 8–9 тепер живе в **трьох копіях**. Запис застосовується на
одній репліці одразу, а до сусідів летить потім — як між дата-центрами. Ви заміряєте,
скільки копії бувають різними, розірвете мережу, побачите, як правило «останній запис
виграє» мовчки губить чужий замір, напишете злиття без втрат і з'ясуєте, коли кворум
каже «ні».

Усе локально, стандартна бібліотека. Ні Docker, ні Redis.

## Що має бути наприкінці

- `zlyttia.py` зі злиттям без втрат — `perevirka_zlyttia.py` показує **6 з 6**;
- `praktyka/12-uzgodzhenist/zvit.md` з **числами**: вікно неузгодженості при двох затримках,
  стан трьох копій під час розриву й після нього — з правилом «останній виграє» і з вашим злиттям,
  відповіді кворуму під час розриву;
- рядок, яку стратегію (CP чи AP) ви обрали б для журналу замірів і для залишку на картці — і чому;
- усе на GitHub, рядок із результатом — у чаті.

**Мінімум для зарахування** — кроки 0–3: заміряне вікно неузгодженості й відтворена
втрата запису після розриву.

**Контрольні точки:** 12:30 — крок 1 · 12:45 — крок 2 · 13:10 — крок 3 ·
13:30 — крок 4 (кінець другої пари) · 14:00 — крок 6, `push` і рядок у чат ·

## Крок 1. Прочитати одразу після запису (10 хв)

```
python kliyent_kv.py dodaty zamiry "Петренко: 3.2 с" --do R1
python kliyent_kv.py chytaty zamiry --z R3
```

✔ `✔ R1, W=1, за 6 мс → 1 зап.: Петренко: 3.2 с [R1]` — запис прийнято.
✔ А R3 відповідає `— (ключа немає)`: запис ще летить.

Зачекайте секунду й прочитайте з R3 ще раз:

✔ `1 зап.: Петренко: 3.2 с [R1]` — копії зійшлися.

Клієнт отримав «✔» і одразу прочитав старе. Ніхто не помилився — це **кінцева
узгодженість**: копії сходяться, але не миттєво.

## Крок 2. Вікно неузгодженості (15 хв)

```
python kliyent_kv.py vikno --do R1 --z R3 --raz 10
```

✔ На ноутбуці викладача: `вікно R1 → R3, 10 разів: медіана 328 мс · мін 325 · макс 357`.

✔ `медіана 79 мс · мін 63 · макс 93`.

У звіт — обидва рядки. Чому вікно завжди трохи більше за затримку реплікації? З чого
складається ця різниця?

Поверніть репліки до звичайних 300 мс (без `--zatrymka-ms`) — далі працюємо з ними.

## Крок 3. Розрив — і запис, що зник (25 хв)

Спільний початок:

```
python kliyent_kv.py dodaty zamiry "Спільний: 9.8 с" --do R1
```

Відріжте R3 від решти:

```
python kliyent_kv.py rozryv R3
```

✔ `✂ R3 | R1 + R2 — зв'язку між ними немає`; репліки пишуть у себе `✂ розрив`.

Тепер — по одному запису з кожного боку. **Спершу на R3, потім на R1:**

```
python kliyent_kv.py dodaty zamiry "Праворуч (R3, раніше): 4.1 с" --do R3
python kliyent_kv.py dodaty zamiry "Ліворуч (R1, пізніше): 3.2 с" --do R1
python kliyent_kv.py stan
```

✔ Дві правди: у R1 і R2 — «Спільний» + «Ліворуч», у R3 — «Спільний» + «Праворуч».

Відновіть зв'язок і подивіться, що лишилось:

```
python kliyent_kv.py zyednaty
python kliyent_kv.py stan
```

✔ На ноутбуці викладача в **усіх трьох**: `2 зап.: Спільний: 9.8 с [R1]; Праворуч (R3, раніше): 4.1 с [R3]`.

Запис «Ліворуч» зник. Його прийняли, клієнт отримав «✔», а тепер його немає ніде —
і жодна репліка не повідомила про помилку. Причому зник саме **пізніший** запис.
Подивіться на `zlyttia.py` і на годинник R3. Чому?

✔ **Мінімум для зарахування — ви тут.** У звіті: три `stan` (до розриву, під час, після)
і пояснення, куди подівся запис.

## Крок 5. Кворум (15 хв)

Розрив, як у кроці 3 (`dodaty` спільного запису, потім `rozryv R3`), і далі:

```
python kliyent_kv.py dodaty zamiry "Меншість, W=2" --do R3 --W 2
python kliyent_kv.py dodaty zamiry "Більшість, W=2" --do R1 --W 2
python kliyent_kv.py chytaty zamiry --z R3 --R 2
python kliyent_kv.py chytaty zamiry --z R3
```

✔ На ноутбуці викладача:

| Команда | Відповідь |
|---|---|
| запис на R3, W=2 | `❌ відмовлено: доступних копій 1, потрібно W=2` |
| запис на R1, W=2 | `✔ … за 328 мс` |
| читання з R3, R=2 | `❌ відмовлено: доступних копій 1, потрібно R=2` |
| читання з R3, R=1 | відповідає — але **без** запису «Більшість» |

У звіті: де тут CP, а де AP? Чому запис із W=2 тривав 328 мс, а з W=1 — кілька мілісекунд?
І чому три репліки, а не чотири?

## Якщо щось пішло не так

| Що бачите | Що це означає | Що робити |
|---|---|---|
| `error: remote shablon already exists` | адресу шаблону вже додано раніше | одразу `git fetch shablon` |
| `ConnectionRefusedError` | репліку не запущено | запустіть усі три |
| `WinError 10048` | стара репліка з тим самим ім'ям ще жива | закрийте її термінал |
| після `zyednaty` копії ще різні | обмін іде з тією ж затримкою | зачекайте секунду й повторіть `stan` |
| після правки злиття запис усе одно губиться | репліки запущені зі старою `zlyttia.py` | перезапустіть усі три |
| `vikno`: «так і не побачив запису» | R3 відрізана після кроку 3 | `python kliyent_kv.py zyednaty` |
| у `stan` лишились записи з минулих спроб | репліки пам'ятають усе до перезапуску | для чистого досліду перезапустіть усі три |
| числа вікна трохи інші | планувальник ОС | важливе співвідношення до затримки |

**⭐2. Розрив не потрібен (10 хв).** Без жодного розриву додайте два записи **майже
одночасно** — на R1 і на R3, двома командами в одному рядку (у PowerShell через `;`).
З правилом «останній виграє» на ноутбуці викладача лишився **1 запис із 2**, з вашим
злиттям — 2. Сформулюйте, за якої умови LWW губить дані навіть у справній мережі.

**⭐3. Хто «новіший» (15 хв).** Повторіть крок 3 з LWW, але запустіть R3 з `--zsuv 0`.
На ноутбуці викладача тепер лишається «Ліворуч», а не «Праворуч». Тобто результат
залежить від того, чий годинник поспішає. Чим замінити час у правилі «останній виграє»,
щоб від годинників нічого не залежало (тема 11)?

**⭐4. Справжня задача: видалення, яке не воскресає (30+ хв).** Додайте дію «видалити запис
за `id`» (у `replika.py`, `kliyent_kv.py` і злиття). Наївно — просто прибрати зі списку.
Видаліть запис на R1 під час розриву й відновіть зв'язок: злиття множин **поверне**
його з R3. Те саме було з кошиком Amazon Dynamo — видалені товари поверталися. Зробіть так,
щоб видалений запис не воскресав, і поясніть, що доведеться зберігати замість нього.
