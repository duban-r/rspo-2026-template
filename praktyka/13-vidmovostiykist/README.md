# Практична 13. Двофазна фіксація зависає

Тема 13, день 1 · до **8 балів** · практика — друга пара й початок третьої ·
з середини третьої пари — **кожен ділиться результатом**

Переказ між трьома банками: з рахунку в U1 знімається 200 грн, U2 отримує 150, U3 — 50.
Або все, або нічого: сума грошей у трьох банках має лишатися **3000 грн**. Це забезпечує
двофазна фіксація — і ви побачите, де цей «правильний» протокол **зависає**, чому учасник
нічого не може зробити сам і скільки коштує одна хвилина такого зависання.

Усе локально, стандартна бібліотека. Ні Docker, ні Redis, ні архіву підручника.

## Що має бути наприкінці

- `praktyka/13-vidmovostiykist/zvit.md` — шість сценаріїв із **виводом**: часова шкала
  координатора, `stan` трьох банків, скільки секунд був заблокований рахунок;
- відповідь своїми словами: **що учасник у стані «готовий» може зробити сам** — і чому;
- усе на GitHub, рядок із результатом — у чаті.

**Мінімум для зарахування** — кроки 0–3: звичайний переказ, скасування за голосом «ні»,
зависання після падіння координатора з поясненням.

**Контрольні точки:** 12:30 — крок 1 · 12:50 — крок 2 · 13:10 — крок 3 ·
13:30 — крок 4 (кінець другої пари) · 14:00 — крок 7, `push` і рядок у чат ·
14:10 — ділимось результатами.

Застрягли більше ніж на 5 хвилин — напишіть у чат номер кроку й **скопійований** текст помилки.

## Стенд: три файли й чотири термінали

| Файл | Що це |
|---|---|
| `uchasnyk.py` | банк з одним рахунком (1000 грн). Голосує, пише кожен крок у `zhurnal-<ім'я>.txt`, поки «готовий» — **блокує рахунок** |
| `koordynator_2pc.py` | одна транзакція: фаза 1 (голосування), фаза 2 (рішення). Вміє падати в заданий момент і `--vidnovyty` за своїм журналом |
| `kliyent_bank.py` | `stan` — залишки, хто заблокований, загальна сума; `znyaty U1 50` — звичайна операція; `rozpytaty T-…` — хто що знає про транзакцію |

```
                 ┌──► U1 :50061  (−200)
koordynator_2pc ─┼──► U2 :50062  (+150)        фаза 1: «готові?» → «так» / «ні»
                 └──► U3 :50063  (+50)         фаза 2: «фіксуємо» / «скасовуємо»
```

## Крок 0. Три банки (5 хв)

Три термінали, у кожному — тека `praktyka/13-vidmovostiykist`:

```
python uchasnyk.py --imya U1
python uchasnyk.py --imya U2
python uchasnyk.py --imya U3
```

✔ `[U1 …] слухаю :50061 · залишок 1000 грн`.

Четвертий термінал — для координатора й клієнта.

⚠️ Учасники пишуть журнали `zhurnal-U*.txt`. Щоб почати з чистого аркуша — зупиніть усіх
трьох, видаліть `zhurnal-*.txt` і запустіть знову.

## Крок 1. Звичайний переказ (10 хв)

```
python koordynator_2pc.py
python kliyent_bank.py stan
```

✔ Часова шкала на ~90 мс: три `← … tak`, `рішення: ФІКСУЄМО (записано в журнал)`, три `→ … zafiksuvaty`.
✔ `U1: 800 · U2: 1150 · U3: 1050` і `разом: 3000 грн ✔`.

Подивіться в термінали учасників: кожен пише `голосую ТАК … рахунок заблоковано, чекаю рішення`,
а потім `✔ ЗАФІКСОВАНО … рахунок був заблокований 0.0 с`.

## Крок 2. Хтось каже «ні» (10 хв)

У U1 тепер 800 грн, а ми спробуємо зняти 5000:

```
python koordynator_2pc.py --suma 5000
python kliyent_bank.py stan
```

✔ `← U1: ni`, решта `tak`, рішення `СКАСОВУЄМО`, U2 і U3 отримують `skasuvaty`.
✔ Залишки не змінились, `разом: 3000 грн ✔`.

Атомарність: один «ні» — і не змінилось нічого ніде. У звіті: навіщо U2 і U3 узагалі отримують
«скасувати», якщо гроші в них іще не зарахували?

## Крок 3. Координатор падає між фазами (20 хв)

```
python koordynator_2pc.py --vpasty pislia-holosuvannia
python kliyent_bank.py stan
```

✔ `💥 координатор падає: голоси зібрано, рішення ніхто не почув`.
✔ Усі троє: `🔒 ГОТОВИЙ по T-… уже 0.1 с — рахунок заблоковано`.

Спробуйте звичайну операцію — зняти готівку в U2:

```
python kliyent_bank.py znyaty U2 50
```

✔ `❌ U2: рахунок заблоковано транзакцією T-… уже … с`. Повторіть через хвилину — секунди ростуть.

Тепер найважливіше питання дня — у звіт, своїми словами:
**учасник U2 проголосував «так» і чекає. Що він може зробити сам?**
Розгляньте обидва варіанти — «зафіксую сам» і «скасую сам» — і для кожного поясніть,
за якого рішення координатора це зламає атомарність.

✔ **Мінімум для зарахування — ви тут.** Не скасовуйте поки нічого: учасники мають лишатися «готовими».

## Крок 4. Перезапуск не допомагає (10 хв)

Закрийте термінал U2 (`Ctrl+C`) і запустіть знову:

```
python uchasnyk.py --imya U2
```

✔ `відновлено з журналу: залишок 1000 грн · ⚠ ГОТОВИЙ по T-… — рішення не знаю, рахунок заблоковано`.

Учасник пообіцяв «так» і записав це на диск **до того, як відповісти**. У звіті: що зламалося б,
якби він записував обіцянку після відповіді — або не записував узагалі? (Перевірити — ⭐3.)

## Крок 5. Координатор повертається (10 хв)

```
python koordynator_2pc.py --vidnovyty
python kliyent_bank.py stan
```

✔ `рішення в журналі немає → СКАСОВУЄМО (ніхто не міг його почути)`.
✔ Усі вільні, залишки 800 · 1150 · 1050, `разом: 3000 грн ✔`; учасники пишуть,
скільки секунд рахунок був заблокований.

Чому координатор має право скасувати, якщо в його журналі немає рішення? І що б він мусив
зробити, якби рішення в журналі було?

## Крок 6. Рішення почув лише один (15 хв)

```
python koordynator_2pc.py --vpasty pislia-pershoho-rishennia
python kliyent_bank.py stan
```

✔ `рішення: ФІКСУЄМО (записано в журнал)` → `→ U1: zafiksuvaty` → `💥 … рішення почув лише U1`.
✔ U1 — вільний і вже з новим залишком; U2 і U3 — `🔒 ГОТОВИЙ`;
`разом: 2800 грн ⏳ має бути 3000: хтось іще чекає рішення`.

Хто що знає (підставте свій номер транзакції):

```
python kliyent_bank.py rozpytaty T-xxxx
```

✔ `U1: знає рішення: zafiksovano` · `U2: проголосував «так», рішення не знає` · `U3: …не знає`.

Відновіть координатора: `python koordynator_2pc.py --vidnovyty` → `у журналі рішення «zafiksovano»
→ розсилаю всім ще раз` → `разом: 3000 грн ✔`.

У звіті: якби U2 міг спитати U1 напряму, чи вийшов би він із зависання? А в кроці 3?

## Якщо щось пішло не так

| Що бачите | Що це означає | Що робити |
|---|---|---|
| `error: remote shablon already exists` | адресу шаблону вже додано раніше | одразу `git fetch shablon` |
| `← U1: мовчить (ConnectionRefusedError)` | учасника не запущено | запустіть усі три |
| у кроці 1 голос `ni` з причиною «заблоковано іншою транзакцією» | лишилось зависання з попередньої спроби | `python koordynator_2pc.py --vidnovyty` |
| залишки не 1000 на старті | учасники відновились зі старих журналів | зупиніть, видаліть `zhurnal-*.txt`, запустіть знову |
| `журналу координатора немає` | координатор ще не запускався в цій теці | спершу будь-яка транзакція |
| `WinError 10048` | старий учасник ще живий | закрийте його термінал |
