## Крок 2. Скільки ядер реально працювало (10 хв)

Функція `process_time()` рахує процесорний час **усіх потоків** програми
(ви читали про неї в самостійній тижня 2). Поділіть його на звичайний час — і дізнаєтесь,
скільки ядер працювало в середньому.

```python
from time import perf_counter, process_time

def navantazhennya(fn, *a):
    c0, t0 = process_time(), perf_counter()
    fn(*a)
    return (process_time() - c0) / (perf_counter() - t0)
```

У блок запуску:

```python
    print("процесорний / настінний, 8 потоків:", round(navantazhennya(potokamy, 8), 2))
```

✔ Число **0,9–1,0** — вісім потоків, а працювало одне ядро.
Необов'язково: відкрийте диспетчер задач під час запуску — загальне навантаження
процесора ≈ 100 % ÷ кількість логічних ядер.

## Крок 3. Задача з очікуванням (15 хв)

Та сама структура коду, але робота — не обчислення, а очікування.

```python
import time

def zapyt(nomer):
    time.sleep(0.5)          # «запит у мережу»: процесор вільний
    return nomer

def ochikuvannya_poslidovno():
    return [zapyt(i) for i in range(32)]

def ochikuvannya_potokamy(n):
    with ThreadPoolExecutor(max_workers=n) as ex:
        return list(ex.map(zapyt, range(32)))
```

У блок запуску:

```python
    t0 = perf_counter()
    base_o = ochikuvannya_poslidovno()          # один прогін: 16 с, розкиду тут немає
    t_base_o = perf_counter() - t0
    print("очікування послідовно", round(t_base_o, 2))

    for n in (2, 4, 8, 16, 32):
        t, chasy, r = zamir(ochikuvannya_potokamy, 3, n)
        assert r == base_o
        print("очікування, потоків", n, [round(c, 2) for c in chasy],
              "прискорення", round(t_base_o / t, 1))
```

✔ Послідовно ≈ **16,0 с**; 2 потоки ≈ 8,0 с; 16 потоків ≈ 1,0 с (**×16**); 32 потоки ≈ 0,5 с (**×32**).

## Якщо щось пішло не так

| Що бачите | Що це означає | Що робити |
|---|---|---|
| `AssertionError: результат розійшовся` | порядок рядків змінився | використовуйте `ex.map` — він зберігає порядок; не `as_completed` |
| `NameError: name 'ryadok' is not defined` | скопійовано не весь код тижня 2 | скопіюйте весь `mandelbrot.py` |
| `TypeError` у `zamir(potokamy, 3, n)` | інша сигнатура `zamir` | на тижні 2 вона `zamir(fn, prohoniv=3, *a)` — звірте свою |
| потоки на обчисленнях дали ×2 і більше | Python без GIL або обчислення не на чистому Python | `python -c "import sys; print(sys._is_gil_enabled())"` — запишіть результат у висновки, це цікаво |
| `AttributeError: _is_gil_enabled` | Python 3.12 або старший | GIL точно увімкнено — так і запишіть |
| очікування не прискорюється | у `ex.map` передано результат виклику | `ex.map(zapyt, range(32))` — функція **без дужок** |
| прискорення на обчисленнях менше 1 (0,6–0,9) | потоки повільніші за послідовно | це нормально: ціна черги за GIL. Запишіть як є й поясніть |
| скрипт іде понад 5 хвилин | завеликий розмір задачі | поверніть розмір із тижня 2 (один прогін 5–15 с) |
| `ModuleNotFoundError: No module named 'matplotlib'` | не встановлено | `pip install matplotlib` або графік в Excel / Google Таблицях |
| `git push` — `rejected` | на GitHub є зміни, яких немає у вас | `git pull`, потім знову `git push` |
